    How to calculate VLSM step by step

    The example loaded above is 192.168.1.0/24 (256 addresses) and four subnets that need 60, 30, 12 and 2 hosts. Work it by hand the same way the table does.

    1. Sort by hosts, largest first: LAN 60, Staff 30, Lab 12, Link 2.
    2. Add 2 for the network and broadcast addresses, then round up to a power of two. 60 + 2 = 62 → 64. 30 + 2 = 32 → 32. 12 + 2 = 14 → 16. 2 + 2 = 4 → 4.
    3. Those sizes are the prefixes. 64 addresses is a /26 (255.255.255.192). 32 is a /27 (255.255.255.224). 16 is a /28 (255.255.255.240). 4 is a /30 (255.255.255.252).
    4. Start at 192.168.1.0. LAN takes 192.168.1.0–192.168.1.63, so the next subnet starts at 192.168.1.64. Staff takes 192.168.1.64–192.168.1.95 (hosts .65–.94, broadcast .95), and the next starts at 192.168.1.96. Lab takes 192.168.1.96–192.168.1.111 (hosts .97–.110, broadcast .111), and the next starts at 192.168.1.112. Link takes 192.168.1.112–192.168.1.115 (hosts .113–.114, broadcast .115).
    5. The four blocks use 64 + 32 + 16 + 4 = 116 addresses. 140 of the /24 are still free, beginning at 192.168.1.116. Inside the subnets, LAN has 2 unused hosts (62 usable, 60 needed) and Lab has 2 (14 usable, 12 needed). Staff and Link waste none.

    How to calculate the VLSM subnet mask

    The mask comes from the host count, not from the parent. Add 2, round up to a power of two, and that block size is the prefix. The prefix written as 32 ones and zeros, in dotted decimal, is the subnet mask. A /26 is 26 ones: 255.255.255.192.

    60 hosts are not a row of their own: 62 rounds up to the same 64-address block as 62 hosts, so the mask is still 255.255.255.192. Open any row in the Subnet calculator, or look up the prefix on the CIDR cheat sheet.

    Capacity rule changes the math, not just the label. The generic rule reserves the network and broadcast addresses, and the /31 and /32 options give two-host links and single-host requests (loopbacks, host routes) their smallest legal blocks. AWS VPC and Azure VNet reserve five addresses per subnet (the first four and the last) and enforce a minimum size (/28 and /29); Google Cloud reserves the first two and the last two and enforces /29. The first and last usable address in the table follow those positions, and AWS also caps a subnet at /16, so a request that would need a larger block is rejected. A 60-host request gets a /25 on AWS instead of a /26, and the cloud exports show no warnings because the plan was built under the same rule.

    To check one of the subnets in detail, open it in the subnet calculator. The subnetting tutorial works through a VLSM design by hand. For fixed, ready-to-read plans, see the AWS three-tier VPC and Azure hub-spoke examples.

    Questions

    What is VLSM?

    Variable Length Subnet Masking gives each subnet its own prefix length, chosen from how many hosts that subnet needs. A 60-host LAN can take a /26 while a point-to-point link takes a /30, instead of forcing every subnet to share one mask.

    What is the difference between VLSM and FLSM?

    FLSM (fixed-length subnet masking) cuts a network into equal pieces, so every subnet has the same mask. VLSM allows different masks inside one parent. FLSM is simpler to write out; VLSM leaves fewer unused addresses when the host counts differ.

    Why allocate the largest subnet first?

    A subnet has to start on a multiple of its own size. Placing the largest block first keeps every smaller block that follows aligned, with no gaps. In that order, a list fits whenever the sum of the block sizes fits in the parent.

    What happens if the subnets don't fit?

    The calculator names the subnet that does not fit, how many addresses are left, how many the plan is short by, and the smallest prefix that would hold every request. It does not drop a subnet or return a partial plan without saying so.

    Does VLSM apply to IPv6?

    IPv6 LANs are almost always a /64, so sizing a subnet from a host count is an IPv4 practice. You still split a large IPv6 prefix into smaller prefixes, such as a /48 into /56 site blocks. That is prefix planning, which the IPv6 subnet plan does, rather than this host-count calculator.
