Privacy and Data Handling

The calculators are ordinary static pages: the arithmetic runs in your browser, and there is no account or database. The two places data can travel are share links and optional analytics, both described below.

Calculations are local

Address parsing, subnet math, VLSM planning, aggregation and IPv6 tools all run as JavaScript in your browser. What you type is not posted to the site: there is no API call and no form submission behind the results. The page files themselves are served by a static host, and the site keeps no copy of your input.

What a share link contains

When you use a share button, the current inputs are placed in the link's query string, for example /?q=192.168.1.0/26 or /vlsm/?p=10.0.0.0/24&r=Sales:120. That is what makes the link reproduce your result.

Because the values are in the URL, opening the link sends them to the host serving the page as part of the request, where they may appear in standard server or CDN logs. This is normal web behavior, not something the site reads or stores itself. Treat a share link like the input it carries: do not post links containing addresses, department names or plans you would not share with the recipient.

Analytics

Analytics are off by default. The site is built to load Google Analytics 4 and Microsoft Clarity only on subnetcalc.dev, only after the page becomes idle, and only when measurement IDs are configured. At present no IDs are configured, so no analytics script is loaded.

If analytics are enabled, they record page views and a small set of events: a calculation completed, a copy, a share, a download, and the type of an input error. Page views and events are sent with the path only (no query string or fragment), an input-free page title, and a referrer stripped of its query string and fragment; the automatic page view that would carry the address bar is disabled. Event metadata is restricted to short fixed values such as the tool name, the event kind, an error code, a format name or a count. Addresses, MAC addresses, subnet names, host counts and full parameter URLs are never sent as event data. The providers may set their own cookies or identifiers; see the Google privacy policy and the Microsoft privacy statement.

Local storage and hosting

The site stores two things in your browser, both optional: the chosen theme (system, light or dark) and any VLSM plans you explicitly save. Both are kept in localStorage, are never uploaded, and can be removed by deleting the plan or clearing site data. Saved plans hold only the planner inputs (parent, subnet names and host counts, capacity rule and options), not addresses or results from other tools.

Hosting is static, with no accounts, no cookies set by the site itself and no server-side database. The hosting provider processes standard request data (such as IP address, user agent and requested path) to serve and protect the site under its own terms.

Contact

Questions or corrections: open an issue at github.com/heymi/Subnetcalc/issues. The verification page explains how results are checked and how to report a wrong one.
